Evidence for spec.md. Twelve independent read-only reviewers, one per subsystem, each
reading the area's architecture doc then the code in full; every BAD item verified by its
reviewer in surrounding code, six headline items re-verified by the coordinator. Confidence
0-100 as reported. Line numbers are as of commit 26409fc99; treat as anchors, re-locate
before editing. Spec requirements reference these ids; plan.md maps each id to a task.

Severity: L = data loss / silent corruption, C = crash / hang, S = silent wrong state,
T = security / trust, P = performance, B = build / CI, D = debt (duplication, drift, dead
code), V = missing verification.
